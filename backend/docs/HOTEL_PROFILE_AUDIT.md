# Hotel profile and photo audit events

GEN-07 with HTL-01/09/10 and GEN-08. Hotel creation, profile edits, policy changes and image addition/removal now commit their audit effect with the business metadata in one retrying MongoDB transaction. Existing role, actual provider assignment, DTO/city validation and five-image cap remain enforced. Hotel room, booking/inventory and payment implementations are preserved.

The additive event/action names are hotel.created, hotel.updated, hotel.policies_updated, hotel.image_added and hotel.image_removed. Each records the real authenticated actor and hotel target. Photo events additionally record the public image ID. Profile bodies, addresses, credentials and payment data are omitted. The existing canonical admin history supports these filters and shows pending committed effects immediately. Omar's unchanged generic consumer archives them idempotently; retained envelopes and archived copies count once, and the archive remains readable after envelope removal.

Image creation happens before the metadata transaction. If that transaction or audit write fails, only the new file is removed. Image removal deletes the original file only after the transaction commits; rollback retains both metadata and file. As with the shared media service, cleanup is best effort across process crashes. No filesystem/database distributed transaction or optional orphan worker is claimed.

Ten real HTTP/database/consumer/filesystem tests exercise all five actual producers, immediate and delivered history, archive retention, private projection, permissions, validation, create/edit/policy/photo failure rollback, concurrent partial edits, concurrent cap enforcement, filtering, pagination and Swagger. Existing history tests now include the genuine hotel-creation action in setup totals and delivery, preserving their original source/filter/privacy assertions. A complete-AppModule check independently verifies all 110 mandatory method/path pairs from the checksum-pinned official PDF; nine explicitly optional route entries are excluded.

Typecheck, build, lint and all 209 unit tests passed. The complete fresh HTTP/database regression passed all 647 cases in 27 suites. Uses disposable databases/configuration and actual domain modules; external payment responses alone are controlled. No private environment, shared database or live payment operation was used.

Swagger demo: log in as an administrator, create/edit a hotel or add/remove a photo, then filter GET /api/admin/audit-logs by the relevant hotel action. The assigned hotel moderator may edit their profile/policies/photos but cannot read the administrator audit endpoint. Normal workers deliver the pending audit; both pending and delivered records represent committed business actions.
