# Flight search, details and itinerary reuse

Mandatory FLT-11/12/15/17/30 and ITN-26. The same actual flight/airline/reference/hold services serve the anonymous search and the owned itinerary route; no inventory, payment or location data is fabricated.

- GET /api/flights/search requires departureAirportCode, arrivalAirportCode and departureDate (the departure airport's calendar date). Both airports must be in the official reference source, differ, and the date cannot be past locally. Optional returnDate requests reversed-route options on that airport's local departure date.
- passengers defaults to one and includes children/infants. children and infants default to zero; remaining passengers are adults. At least one adult is required and infants cannot outnumber adults. Adults/children need a seat and pay the cabin fare; infants pay ten percent, rounded to integer cents exactly like the held quote, without a seat. Birth dates/types are checked again during the actual booking flow.
- Only future Scheduled flights of active airlines qualify. Every returned cabin independently has enough total-minus-booked-minus-held seats. Expiry reconciliation releases lapsed unpaid holds before availability is read. Cancelled/departed flights and inactive providers are excluded. Each flight appears once with its eligible cabin choices.
- cabinCategory selects one of the four fixed classes. minPriceMinor/maxPriceMinor are inclusive whole-party USD-cent fare filters for each leg before extra bags; reversed ranges fail. sortBy is price, duration or departureTime; order is asc/desc. Price sort uses the cheapest eligible cabin. Stable ten-flight pages use page and independent returnPage, both defaulting to one. Empty matches return empty data and zero totals. A shared MongoDB aggregation filters/group/facets rows and count together.
- The response has criteria, outbound and nullable inbound, each leg using data/meta. It positively projects airline name/code/logo, airports/IANA zones, local and UTC times, duration, cabin price/availability/baggage and current cancellation policy. No user, passport, payment or internal fence fields are returned. Choosing two options does not reserve them; hold creation validates the reversed route, outbound arrival/return order and current inventory atomically.
- GET /api/flights/:id is anonymous and shows current active-provider flight details, all cabins and policies. A Scheduled flight whose departure has passed is displayed as Departed without a write. Cancelled status remains visible by direct link but is excluded from search. An inactive provider returns 404; already paid owners still have their saved private booking details.

GET /api/itineraries/:id/flights requires an active owner traveler session, including when the itinerary is public. Choose originAirportCode. The current first day supplies the destination city, and every official airport in that city participates. departureDate defaults to the itinerary start; roundTrip=true defaults the return to the last day's derived date. An explicit returnDate also enables return search. Date overrides and the same passenger/cabin/price/sort/page filters are accepted; caller-supplied destination/first-city overrides are rejected. Empty itineraries return 400. Current ordering, city edits and start-date changes are read afresh, so there is no stale destination/date cache. The response adds selection with the derived city/airports/dates. No booking/payment is created.

All responses are no-store. Malformed fields, unsupported query/operator fields, bad dates/counts/ranges/pages and identical public airports return 400; unknown references return 404. Unseeded official reference data fails as unavailable. Itinerary guests receive 401, other roles 403 and foreign/missing trips 404. Flight creation keeps the existing authenticated/assigned-moderator policy; public reads have no cookie requirement in Swagger.

Verification uses the existing real flight integration fixture with official disposable reference seeding and actual HTTP/database transactions. Search cases cover local-versus-UTC date boundaries, availability/expiry and inactive/departed/cancelled providers, grouped cabins, inclusive filters/sorting, infant half-cent rounding against a real hold, pagination, one-payment round-trip reuse, input/permission rejection, itinerary defaults/reordering/date overrides and Swagger numeric/public/private contracts. No private .env, shared database or live Stripe operation is used.

Typecheck, build, lint and 209 unit tests passed. The flight HTTP/database suite passed all 58 cases (26 new search/itinerary cases), and the fresh remaining regression run passed all 522 cases: 580 total across 23 suites. Databases/configuration are disposable; no private .env, shared data or live Stripe action was used.
