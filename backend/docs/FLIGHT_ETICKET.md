# Private flight e-ticket PDF

Mandatory FLT-23 with GEN-06/ACC-11. `GET /api/flight-bookings/:id/e-ticket` requires an active, unrestricted traveler session and that exact booking owner. Missing/foreign bookings return 404; unpaid, Expired and Cancelled bookings return 409. Confirmed and Completed bookings remain downloadable, including history from a provider that is no longer active. Administrators and moderators do not inherit this private traveler download permission.

The PDF contains the actual confirmed reference, every saved outbound/return segment, airline/flight/airport names, airport-local dates/times with UTC offsets and official IANA zones, matching cabin/seats, saved baggage allowance and passenger extra bags/weights, names/types and exact USD total. Active schedule changes already propagate into booking segments through the verified flight-management transaction; the ticket uses those saved segments. Prices/policies remain the booking's saved quote. Birth dates, identity documents, owner contacts, payment IDs, credentials and card data are not selected for the ticket.

The response is an application/pdf attachment with a validated-ID filename, no-store and nosniff. Generation neither confirms a booking nor changes inventory/payment state. It creates no public file or persisted download URL, and makes no external image/font/airline request. Required reference lookup still enforces the official source readiness marker.

PDFKit 0.20.2 runs in the existing Node/Nest process. Unmodified OFL Noto Sans and Noto Sans Arabic fonts, their licenses, sources and SHA-256 hashes are versioned under src/assets/fonts. Nest copies those assets into dist/assets/fonts. Text uses complete-line shaping and preserves precomposed Arabic characters in the PDF Unicode map; long names wrap and additional passengers create numbered pages. A narrow documented type adaptation covers PDFKit's supported feature-map option, which the older TypeScript definition models only as an array. No system font, Python runtime or shared database migration is required.

Eight real HTTP/disposable-database tests independently parse the generated documents with development-only Mozilla PDF.js 4.10.38. A bounded native-Node helper keeps its ESM/typed-array implementation outside Jest's VM; no application configuration is loaded. Assertions cover actual schedule offsets, names, saved baggage, exact total, private-data exclusion, guest/role/owner/password/account/state guards, read-only completed history, both segments, all passengers/page numbers, accented/Arabic/maximum-length names and binary Swagger metadata. The paid-flight integration test additionally denies an unpaid ticket, then downloads after real SDK-signed success through the actual settlement adapter. External payment responses remain controlled.

The actual synthetic HTTP downloads were rendered with checksum-verified Poppler and all seven pages inspected: one-way, a four-page round trip with eighteen long passenger names, and a two-page accented/Arabic/150-character-name case. Margins, wrapping, word order, page numbers and footers were checked. An older attempted parser was replaced after native extraction and Poppler isolated its Unicode/VM limitations; the Arabic equality checks remain exact.
